Data flow

Current: accepted turns and preferences live in browser localStorage. Input counsel and generation candidates are transient. Proposed: save a draft separately and keep candidates unscored until acceptance. A cloud model configuration would change the text privacy boundary.

A1: Odysseus advice interpretation

Model: Llama 3.2 3B via local Ollama

Input: Reviewed counsel, current scene and temptation, trust 0-100, safe/risky actions and source context.

Output: JSON: reply, reason, safeChoice, followed and tone. Server supplies months, trust change and authored consequence.

Timing: Measured 8.87-38.43 seconds, mean 26.36 seconds. Use the six-call measurements in the technical spike. Allow 90 seconds on the server and 95 seconds in the browser.

Privacy: Text goes to loopback Ollama in this setup. No account or third-party text inference is needed. A cloud endpoint would send that same payload outside the device and would require a revised disclosure.

Control: Existing retry and explicit Story mode fallback. Proposed review, refine counsel and discard a questionable candidate before score changes.

A2: Optional speech input

Model: Browser speech service or Windows voice typing. Provider/model unspecified.

Input: Microphone audio after the player initiates dictation.

Output: Editable transcript. Only a reviewed transcript reaches A1 after Send counsel.

Timing: No microphone timing was measured. Current browser start deadline is 15 seconds, listening limit is 60 seconds and finishing limit is 3 seconds.

Privacy: Audio can reach the browser/OS speech provider. The app has no audio-upload endpoint and stores no audio files. Provider retention is outside this project's verified scope.

Control: Current stop/cancel, transcript review and typing alternative. Proposed explicit uncertain-transcript state.

A3: Optional spoken replies

Model: Browser speech synthesis, installed/browser voice. Piper is not integrated.

Input: Odysseus' accepted text reply.

Output: Speech while the written result remains visible.

Timing: Speech start latency is unmeasured. It does not block reading or advancing the text result.

Privacy: Voice processing may depend on the selected browser/OS voice. The app does not assume every voice runs locally.

Control: Current opt-in setting and cancellation on navigation. Proposed Stop reading, replay, voice-check and playback-error message.

Five persona-linked user flows

F1: Start or resume a voyage

P2 Daniel / Current behavior with proposed practice option

States: S01, S02, S03, S09, S11, S12

  • Success: the player reaches a usable encounter without technical help.
  • Resume preserves the saved route, time, trust and log.
  • If saving fails, show a persistent warning and keep the voyage usable in memory.
  • Proposed practice mode disables the scored challenge and permits local undo.

F2: Give counsel and review the AI decision

P1 Maya and P3 Rosa / Current input/result loop. Review checkpoint and cancel are proposed.

States: A1-INITIAL, A1-LOADING, A1-SUCCESS, A1-UNCERTAIN, A1-ERROR

  • Current code applies a valid decision immediately. The proposed checkpoint separates candidate generation from score commitment.
  • LLM structure validation cannot prove meaning. User-reported mismatch and ambiguous counsel enter review without invented confidence numbers.
  • Regeneration uses the same scene and draft. Each discarded candidate remains unscored.
  • After commitment, Next shore advances. Practice undo restores the full prior route, score, trust and log.

F3: Dictate and correct counsel

P2 Daniel / Current editable transcript and typing alternative. Uncertainty warning proposed.

States: A2-INITIAL, A2-LOADING, A2-SUCCESS, A2-UNCERTAIN, A2-ERROR

  • Send stays unavailable during an active dictation session.
  • Voice never submits counsel automatically.
  • Brave on Windows provides guidance rather than claiming to open the OS voice panel.
  • No acoustic emotion analysis. No claim that speech models match the Phase 1 five-model proposal.

F4: Recover from a failed or questionable result

P1 Maya and P3 Rosa / Current error retry/fallback. Candidate review and discard are proposed.

States: A1-ERROR, A1-UNCERTAIN, S11

  • A 429 response is covered by existing error mapping but was not induced against the local provider.
  • Malformed JSON and missing model are real provider failure tests in this spike.
  • A 1ms timeout records a client failure, not an invented model response.
  • A reported mismatch cancels a pending candidate. Undo of committed turns is available only in proposed practice mode.

F5: Explain a consequence and finish the voyage

P1 Maya, P2 Daniel and P3 Rosa / Current explanations, route and report. Practice undo proposed.

States: S03, S07, S08, S10, S04

  • A safe route can shorten the journey at the wind bag or cattle. The map must follow the saved route.
  • A scored voyage retains committed choices. Practice undo restores route changes as well as numeric values.
  • Sources distinguish Homer's account from game dialogue and counterfactual outcomes.
  • Closing overlays returns focus to the control that opened them.

Technical spike

Six sequential realistic inputs through the production POST adapter in a standalone script. Capture each actual provider response separately from the adapter response. Wall-clock latency includes provider request, JSON parsing and validation. Failure timings are excluded from success statistics.

8.87sMinimum
26.36sAverage
38.43sMaximum

Six sequential calls on local CPU inference, including the first call with no loaded model. Single run with no repeated trials. These are wall-clock adapter timings, not a guaranteed service level.

InputPurposeSecondsReview
S1Supportive safe counsel38.426Leaves the lotus shore as requested. Reply and safeChoice agree.
S2Negation with safe counsel28.948Correctly handles do not open. Rationale is loosely expressed but the chosen action is clear.
S3Polite dangerous counsel8.867Chooses the requested risky opening. Polite danger is not automatically safe. Direct tone is arguable.
S4Direct safe counsel25.425Chooses silence as requested, but followed=false. Supportive tone is also questionable for these imperatives.
S5Motivated safe counsel in another scene29.379Asks Circe and prepares departure as requested, but followed=false.
S6Ambiguous advice with no chosen action27.135The player requests no definite action. followed=true contradicts the prompt's no-action rule. Tone does not acknowledge uncertainty.

All six replies passed structure validation and described actions consistent with safeChoice. S4, S5 and S6 have followed-flag disagreements. This small, single-run sample does not establish a production error rate. It does not erase the previously recorded September 23 reply/safeChoice contradiction.

Rate limits: no 429 occurred in this sequential local run. No quota threshold was measured. The adapter handles 429, but sustained concurrency was not tested. Cost: this loopback run used no billed inference API. Hardware, electricity and cloud-provider costs were not measured.

Design consequences: elapsed wait feedback and cancel for long calls, retain/retry counsel after failures, explicit Story mode fallback, and a review checkpoint for semantic disagreements. Retain Llama provisionally and evaluate flags before relying on AI scoring.
