# Farshore

A playable CMPS 4200 HCI prototype based on Bibek Pathak's Farshore Phase 1 presentation. Advise Odysseus in free text, watch him choose, and reach Ithaca before twenty total years pass.

See README.md for laptop setup. The project notes below describe the game design and its original hosted edition.

## What works

- Retro title screen, a four-scene skippable prologue, animated pixel portraits, six landscape backdrops, and optional short game tones.
- Eleven authored encounters following the journey from the lotus shore to Ithaca.
- A character book with twenty canonical figures, a voyage map, and a pause menu.
- Free text advice, optional browser dictation, and optional spoken replies.
- Decisions influenced by wording and trust in the scripted mode.
- Time budget, trust changes, win/loss endings, and a complete captain's log.
- Explanations distinguish following advice from making a safe choice.
- Device-local saved progress. No accounts or cloud saves.
- Responsive navy, teal, and gold game interface with locally bundled pixel font and original generated art.

The score starts at 120 months, representing ten years at Troy. Each encounter adds its authored travel time or penalty. At 240 months the player loses. Eleven completed encounters below 240 months win. This is a counterfactual retelling, not a literal simulation of the poem. The episode order follows the journey; the poem tells some events as flashbacks. Not every figure or event in the poem is included.

## AI connection

The initial deployment has no model credentials. It runs in clearly labeled **Story mode**, which is a small wording-rule engine, not a pretrained AI model. It does not satisfy the course's AI integration requirement on its own.

`server/turn.ts` supports an OpenAI-compatible chat-completions endpoint. The server validates model JSON and owns the time costs, trust changes, and scene outcomes. The model interprets advice, chooses an action, explains its decision, and writes Odysseus' reply. No API key is sent to the browser.

Copy `.env.example` to `.env` for local development and set:

- `FARSHORE_MODEL_URL`: complete chat-completions URL.
- `FARSHORE_MODEL_NAME`: a model served at that endpoint.
- `FARSHORE_API_KEY`: optional server-side credential.

For the original local Llama plan, install Ollama from its official source, pull `llama3.2:3b`, and use `http://127.0.0.1:11434/v1/chat/completions` with model `llama3.2:3b` in the local checkout. The hosted Site cannot connect to localhost on your laptop. It requires a reachable HTTPS inference endpoint configured in its server environment. Do not expose an unauthenticated local model service to the internet.

Ollama API reference: https://docs.ollama.com/api/openai-compatibility
Structured outputs: https://docs.ollama.com/capabilities/structured-outputs

Settings enables AI dialogue after checking that the model service responds and lists the configured model. A model error keeps the advice and offers retry or an explicit Story mode submission. The app does not silently substitute scripted responses for an AI request. The model deadline is 90 seconds to allow for cold loading. Local Llama 3.2 3B was verified on September 23, 2026 with real API and browser turns. The adapter requests strict JSON-schema output. See the [verification record](<Farshore Context and Assisment/docs/AI-VERIFICATION.md>) for measured timings and an unresolved dialogue/decision inconsistency. The under-one-second and total laptop memory claims remain unverified.

## Simplifications from the slides

One dialogue model replaces separate text semantics and personality models. Browser speech recognition replaces faster-whisper for this first version, and browser speech synthesis replaces Piper. Acoustic emotion analysis is deferred. The app uses the words in the reviewed transcript, not a claim about the speaker's emotional state. Browser dictation can require internet access and may send audio to the browser's speech provider. Typing remains available if voice support or microphone access fails.

The eleven scenes follow a fixed route so the cast stays grounded in the story. Replay changes your counsel, trust, and outcomes. Scenes are authored, not generated by AI. Broader scene variation can follow user testing without changing the game loop.

## Narrative and art sources

The character book and episode anchors use Homer’s *Odyssey*, especially Books 5–6, 9–14, 16–17, and 21–24. Public-domain primary text: https://www.gutenberg.org/files/1727/1727-h/1727-h.htm (Samuel Butler translation; it uses Roman names for some gods). The game uses familiar Greek names. The Siren portrait represents the unnamed group; it is not an invented named person.

The cinematic reference is Christopher Nolan’s *The Odyssey*: https://www.odysseymovie.com/. This is an independent student project. It uses no film stills, actor likenesses, movie dialogue, or official film assets. Generated portraits are original interpretations of the mythological cast, not historically documented appearances. Their idle movement is CSS animation, not frame-by-frame character animation.

The generated location atlas supplies six shared backdrops. Some episodes reuse a backdrop with different narrative context. It is atmosphere rather than a claim about the poem’s geography. Aeolus’ floating island, the Underworld, and ancient Greek clothing are imaginative representations.

In Homer, the crew opens Aeolus’ bag while Odysseus sleeps; Eurylochus leads the slaughter of Helios’ cattle in his absence. The game’s player can advise alternative outcomes. Scylla’s passage still involves unavoidable loss, even on the wiser route. Dialogue, altered outcomes, trust points, and month penalties are authored for gameplay. The hopeful ending condenses the poem’s conflict and reunion.

## Saves and controls

Version 2 uses `farshore-voyage-v2` in localStorage. Existing version 1 saves are left untouched because the route and score rules changed. Game sounds and spoken replies are opt-in. Scene motion defaults to the system preference. Players can explicitly choose Animated or Still in Settings; Still removes motion and text reveal.

- Enter starts/resumes at the title and advances the intro when no button or input has focus.
- Ctrl/Cmd + Enter sends your counsel.
- Escape opens the pause menu or closes an open overlay.
- All actions are also available by click or touch.
